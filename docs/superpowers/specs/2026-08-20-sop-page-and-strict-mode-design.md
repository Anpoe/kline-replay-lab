# SOP 页面与严格模式设计

## 范围

本阶段把已确认的交易 SOP 设计落成可用的前端功能：

- 新增一个独立的 SOP 页面，展示美股日线、A 股日线、EURUSD 5 分钟三个版本；
- 新增设置页的“交易纪律”分区，提供严格模式、事前规划卡和 SOP 检查三个独立开关；
- 在训练开仓入口接入门禁，严格模式开启后阻止不符合配置的开仓委托；
- 用现有已保存训练的成交与事前决策数据展示样本数、胜率、计划完整度和平均结果。

## 不变量与边界

- 不修改数据库 schema、迁移、API contract、训练快照结构、回放游标、快捷键或执行引擎撮合规则。
- 设置仍通过现有 settings gateway 持久化；新字段由 `normalizeSettings` 向后兼容地补齐。
- SOP 门禁只在训练模式的开仓路径运行，平仓、撤单、实盘观察和现有市场规则校验保持原语义。
- 不修改 `executeBarStep`；门禁在它之前拒绝订单，并复用现有拒单展示与训练事件审计机制。
- 旧设置默认不改变当前行为：严格模式默认关闭；打开后，事前规划卡和 SOP 检查默认开启，但两者可以独立关闭。
- 当前没有对应的三个 SOP 版本时只提示“暂无适用版本”，不阻止其他市场的训练。

## SOP 版本

三个版本先作为稳定的 v1.0 基线：

1. 美股日线版：方向、关键位置、触发确认、失效点/目标。
2. A 股日线版：趋势或突破、位置、交易理由、T+1 与风险边界。
3. EURUSD 5 分钟版：高周期背景、盘中位置、触发确认、点差与风险边界。

页面展示完整规则；严格模式第一阶段执行可由现有事前决策卡可靠判断的结构化硬检查（市场状态、位置、至少两个理由、止损和目标），不伪装成已经完成的 K 线形态识别。

## 门禁逻辑

- 严格模式关闭：开仓行为不变。
- 严格模式开启且需要事前规划卡：必须存在当前 K 线提交的、非自动生成、非补写计划。
- 严格模式开启且启用 SOP 检查：适用版本必须通过结构化计划完整度检查；无适用版本只给警告。
- 任一启用的硬检查失败：创建普通 `OrderRejection`，在现有订单拒绝区域显示，并追加 `sop_gate_blocked` 审计事件。

## 页面数据

SOP 页面只接收 shell 组装好的 DTO，不直接访问数据库或组件内部状态。样本来自已有 `TrainingSessionSummary.habitTrades`，按市场和周期映射到三个版本，统计逻辑放在纯函数中并单独测试。

## 验收

- 设置能保存、刷新后恢复，旧设置仍能被正常归一化。
- 三个 SOP 卡片和详情规则可见；当前训练能标出对应版本；无样本时有明确空状态。
- 严格模式三个开关可独立操作；开关关闭时不会意外拦截订单。
- 针对事前计划、SOP 完整度、无适用版本和旧设置兼容性有自动化测试。
