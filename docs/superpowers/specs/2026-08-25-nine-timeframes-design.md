# 九级 MT4 风格时间周期统一设计

## 背景与目标

当前系统的周期集合分散在训练设置、FX 数据任务、供应商接口和周期聚合逻辑中，只有 `1m / 5m / 1h / 1d / 1w` 五个内部 ID。品种选择器又把没有数据的周期直接过滤掉，导致 A 股、美股只有日线的品种只显示一个周期。

本次改动统一支持九个 MT4 风格周期，并把“可显示”和“可选用”分开：

- 内部 ID 保持项目现有的小写格式，新增 `15m`、`30m`、`4h`、`1mo`，避免改变已有快照、会话和数据库记录中的 `1m / 5m / 1h / 1d / 1w`。
- 界面标签对应 `M1、M5、M15、M30、H1、H4、D1、W1、MN`。
- 所有周期选择入口始终渲染九项；没有真实可用数据的项只置灰并禁用，不额外显示提示文案、title 或错误说明。
- 大周期只在存在同一品种的更小周期数据、且该数据源允许聚合时生成；不能把日线反向生成分钟或小时线。只有日线的 A 股/美股品种仍只启用其真实存在的日线（以及目录明确提供的其它真实周期）。

## 统一周期契约

新增一个稳定的周期目录作为所有前端、服务端和纯逻辑的共同来源，至少提供：

- 有序周期 ID、MT4 显示标签和排序序号。
- 固定分钟周期与日历周期的区分。
- 周期比较、周期是否合法、周期是否可由来源周期向上聚合的纯函数。
- 周期桶起点规则：分钟/小时按时间轴对齐，日/周按品种时区，月线按品种时区的自然月。

现有 `settingsContracts`、`timeframeAggregation`、FX 数据契约、供应商契约和路由不再各自维护周期字面量；旧的公开内部 ID 继续兼容。

## 可用性与界面行为

品种目录中的 `timeframes` 表示该品种实际已有的周期覆盖，而不是 UI 应该渲染的选项集合。训练工作台使用统一周期目录渲染完整九项，再用品种覆盖集合决定是否禁用。

以下入口都采用相同规则：

- 桌面图表周期栏和手机周期栏。
- 训练任务设置中的品种/周期选择。
- 设置中的默认周期和随机训练指定周期。
- 复盘历史周期筛选、绩效周期筛选。
- 数据维护任务、供应商支持周期和 FX 目标周期。

切换品种时只能自动选择该品种的第一个可用周期；不能把不可用周期写入新的训练请求。直接从 URL、恢复会话、随机训练或 API 传入不可用周期时，沿用现有错误/回退边界，不通过禁用 UI 绕过校验。

## 聚合与数据流

### 通用市场

通用 OHLCV 聚合器扩展到 `15m / 30m / 4h / 1mo`。月线按自然月分桶，保留首根开盘、最高最高、最低最低、末根收盘，只有所有输入均有数值时才累加成交量和成交额。聚合不补空桶、不修改输入、不把较大周期拆成较小周期。

快照观察周期继续优先读取目标周期的直接数据；不存在完整直接覆盖时，只有在来源快照周期更小且可聚合时才从来源快照生成。只有日线来源的 A 股/美股不会因此获得分钟/小时周期，数据目录也不会把不存在的周期标记为可用。

### FX

FX 周期契约和 session-aware 聚合器扩展到九项。`M15 / M30 / H4` 使用固定时间桶，`D1 / W1 / MN` 继续使用 FX 交易日、周起点和 17:00 rollover。现有 M1/5m 基准入库流程生成配置要求的上级周期；增量更新按受影响的完整桶刷新，月线不使用固定毫秒数判断自然月边界。

### 供应商与数据任务

供应商的“直接支持周期”和系统的“统一周期目录”保持区分。供应商不支持的新周期不能伪装成直连能力：

- 数据任务参数只接受九个规范 ID。
- 直连供应商仍按其真实能力请求。
- 可以由本地更小周期生成的目标周期走聚合路径。
- 没有可用来源时返回明确的无数据结果，不能写入空的覆盖记录。

不修改数据库 schema、快照格式、交易执行规则或供应商原始响应语义。

## 错误与兼容性

- 周期格式不在统一目录内：API 返回现有参数错误边界。
- 来源周期大于或等于目标周期：不聚合，返回不可生成结果。
- 目标周期无直接数据且来源不足：返回无数据/不可生成结果，前端仅保持该选项禁用，不增加额外提示文案。
- 旧会话、旧快照和旧设置中的五个周期 ID继续可读。
- 旧品种没有覆盖字段时按“没有可用周期”处理，避免把未知数据误显示为可选。

## 测试与验收

新增或更新测试覆盖：

- 九个周期目录的顺序、标签、比较和合法性。
- `15m / 30m / 4h / MN` 的 OHLCV 聚合、自然月边界、时区和 DST 场景。
- FX session rollover、完整桶增量刷新和月线边界。
- 品种覆盖只影响禁用状态，不影响九项渲染；只有日线 A 股/美股的其它周期不可选。
- 设置、复盘、数据任务和快照 API 使用统一周期 ID。
- 不可聚合和无数据请求不会生成快照或覆盖记录。

实现完成后按仓库规则运行受影响测试、`npm run typecheck`、`npm run lint`、`npm run test:unit`、`npm run build`、`npm run verify`、兼容的 `npm test`、`git diff --check`，并更新 CodeGraph 后复查关键入口。
