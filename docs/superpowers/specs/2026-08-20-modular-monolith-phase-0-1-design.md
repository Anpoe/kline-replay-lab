# K 线训练营 2.0 模块化单体 Phase 0–1 设计摘要

## 文档状态

本设计摘要记录已确认的第一阶段架构方向，作为后续实施计划的约束来源。它不是重写方案，也不改变当前交易产品的业务语义。

## 目标

在保持现有功能、数据源行为、交易执行语义和数据库结构稳定的前提下，把 K 线训练营 2.0 从“以 TrainingWorkbench 为中心的页面单体”逐步演进为“有清晰 feature 边界的模块化单体”。

第一阶段只处理安全基线和低风险职责拆分，不进入交易执行引擎、K 线交互核心或数据库 schema 重构。

## 当前架构判断

- `web/app/components/TrainingWorkbench.tsx` 同时承担训练页面布局、回放状态、设置、数据维护、会话历史、复盘、实时扫描、快照和多个 API 调用编排，已经成为变更风险最高的集成点。
- `web/app/lib/executionEngine.ts`、`web/app/lib/marketDataProviders.ts`、`web/app/lib/marketSyncService.ts`、`web/app/lib/reviewMetrics.ts` 等领域逻辑已经具备可复用价值，但边界仍主要由页面调用关系表达。
- `web/db/runtime.ts` 的数据库访问和 schema 初始化被大量 API 与服务直接依赖。第一阶段不改变它的行为，只通过文档和 feature 边界限制新增耦合。
- 当前测试覆盖了若干执行引擎、指标、数据服务和页面渲染场景，但 TrainingWorkbench 主流程的覆盖仍不足，必须先建立可重复的验证基线。
- CodeGraph 已在仓库启用，可用于在每次边界调整前后检查调用者、影响范围和孤立依赖。

## 目标边界

### 训练核心

训练核心负责回放游标、当前行情窗口、订单与持仓、权益曲线、播放控制以及训练流程中的命令编排。它是热状态区域，第一阶段只保留其现有行为，不拆交易规则。

### 设置

设置 feature 负责用户偏好、训练模式、数据源偏好、显示选项和设置持久化的页面编排。它可以请求父级提供当前训练上下文，但不得直接修改训练核心状态，也不得直接访问数据库。

### 市场数据

市场数据 feature 负责数据源选择、覆盖范围、同步/维护入口、供应商配置和数据状态展示。供应商差异在进入页面边界前转换为统一的数据状态，不把供应商响应格式泄漏到训练核心。

### 历史与回顾

历史与回顾 feature 负责会话列表、快照恢复入口、绩效指标展示和历史筛选。它只通过明确的会话/快照输入输出与训练核心交互，不读取训练页面的内部状态。

### 实时扫描

实时扫描 feature 负责扫描条件、扫描结果、刷新状态和结果跳转。它与训练回放隔离，不能通过页面组件直接复用回放内部状态。

### 服务端边界

第一阶段保持现有 API 路由和数据库结构不变。新拆出的 UI feature 只能通过现有 API 或既定的页面回调访问服务端；后续 Phase 2–4 再逐步引入 application、repository 和 provider 边界。

## 迁移原则

1. 先记录现状，再迁移代码；每个迁移单元都必须有前后验证结果。
2. 先拆低风险、低耦合、可独立验证的职责，再处理训练状态、交易执行和图表交互。
3. 以用户流程为边界，而不是按任意文件行数切割。
4. 迁移期间维持 API、数据库 schema、数据供应商语义、订单执行规则和快捷键行为不变。
5. 共享状态只在 feature 边界传递；feature 内部状态优先在 feature 内部管理。
6. 不在第一阶段引入微服务、全量事件溯源、全局状态库或新的数据访问框架。
7. 每个 feature 完成后都要能独立说明：输入是什么、产生什么动作、依赖哪些服务、由哪些测试保护。

## 阶段范围

### Phase 0：安全基线

- 建立类型检查、单元测试、构建、Lint 和统一验证入口。
- 记录 CodeGraph、测试和工作区状态基线。
- 固化架构规则、领域不变量、验证命令和 agent 协作规则。
- 建立关键用户流程的手工冒烟清单。

### Phase 1：低风险 feature 拆分

按以下顺序从 `TrainingWorkbench` 移出职责：

1. 设置与偏好。
2. 市场数据管理与数据源控制。
3. 会话历史与复盘。
4. 实时扫描。
5. 收拢训练页面 shell，明确热状态与冷状态的边界。

每项迁移先提取 feature 自有的 UI 和控制器，再由页面 shell 负责组合；迁移完成后立即进行静态检查、单元测试、构建和相关手工冒烟。

## 明确不在本阶段处理的内容

- 不重写 `TrainingWorkbench` 的训练主循环。
- 不改变 `executionEngine` 的撮合、止损、仓位或资金规则。
- 不拆分 `KLineReplayChart` 的核心交互和绘图状态。
- 不修改数据库表结构、迁移策略或快照格式。
- 不替换现有数据供应商，也不改变数据同步策略。
- 不建设微服务、消息总线或独立部署单元。

## 完成标准

Phase 0–1 完成时，应满足以下条件：

- 原有验证命令仍可运行，并且新增的类型检查、单元测试和统一验证入口均通过。
- CodeGraph 索引保持最新，关键迁移符号的调用者和影响范围有记录。
- `TrainingWorkbench` 保留为组合入口，但不再直接持有设置、数据管理、历史回顾和实时扫描的全部局部状态与副作用。
- 新 feature 之间没有通过页面组件互相读取内部状态的路径。
- 训练回放、下单、撤单、快照保存/恢复、数据维护、历史查看和实时扫描的用户可见行为无回归。
- 没有引入本阶段明确排除的数据库、交易规则或外部数据行为变化。
