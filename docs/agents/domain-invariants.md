# 领域不变量

以下事实是架构迁移必须保持的运行时约束。拆分 UI、控制器或页面组合层时，不得通过改变这些事实来“简化”边界。

## 训练回放

- 回放游标只能按既定训练流程推进、暂停或恢复；不能因为设置保存、数据刷新、历史筛选或扫描刷新而隐式跳动。
- 当前可见 K 线窗口、训练结束边界和任务起始位置必须保持现有包含/排除规则。
- 播放/暂停、单步推进、随机任务、历史任务恢复和刷新后的续训必须保持原有快捷键与用户可见状态。

## 订单、持仓和资金

- 订单状态只能经过现有允许的状态转移；撤单、触发、拒单、部分成交和保护性退出的语义不因 UI 迁移改变。
- 持仓数量、平均成本、已实现/未实现盈亏、现金、保证金和权益必须保持相互一致。
- 止损、止盈、滑点、点差、手续费、保证金、板块交易规则和同 Bar 冲突策略属于交易核心不变量；feature 不得复制或重算这些规则。
- 设置或实时扫描不得直接写订单、持仓或资金；训练 shell 只能接收明确的用户命令或结果跳转事件。

## 快照、会话与复盘

- 保存和恢复必须继续使用现有快照格式、版本和字段语义，不通过 feature 拆分引入第二套序列化格式。
- 恢复顺序必须保持：读取/校验快照 → 准备训练上下文 → 加载数据 → 恢复训练可见状态。恢复失败时不得留下半恢复的训练状态。
- 复盘指标继续使用现有确定性计算逻辑；缺失证据要显式保留，不能用 UI 默认值静默伪造交易证据。
- 历史列表、筛选和删除只影响会话/展示状态，不得改变当前回放中的订单或持仓。

## 市场数据与时间序列

- 进入训练核心的 K 线必须保持现有标准化、排序、时间边界、去重和 OHLC 校验语义。
- 数据源、FX/A 股/美股差异和供应商错误必须在市场数据边界内转换；训练核心不依赖供应商原始字段。
- 数据维护和覆盖范围刷新不得静默替换训练中正在使用的行情窗口；刷新通知由 shell 决定何时重新加载。
- 外部同步不可用时，必须展示可恢复的错误/重试入口；默认验证不得依赖真实网络同步成功。

## 实时扫描隔离

- 扫描请求、筛选条件、结果列表、刷新和错误状态属于实时扫描生命周期，与本地回放生命周期分开。
- 扫描结果只有在用户明确选择并通过 shell 交接后，才能创建新的训练上下文；刷新扫描不得覆盖当前训练任务。
- 结果跳转必须保留现有品种、周期、日期窗口和数据加载约束；不能绕过训练上下文初始化。

## 持久化与接口稳定性

- 第一阶段不修改数据库 schema、迁移策略、API 外部响应契约、快照格式或现有数据供应商行为。
- UI feature 不直接访问数据库运行时；服务端数据访问继续由现有 API、service 和 runtime 入口承担。
- 偏好保存的字段、默认值、错误提示和刷新后恢复行为必须保持兼容，包含遗留字段的清理规则也不能被意外删除。
